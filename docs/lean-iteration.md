# Lean iteration: less coordination, more shipping

Status: all three phases accepted locally. Installed proof and limitations are recorded in `lean-proof.md`. This is an opt-in change, not a migration of active factories; Creator rollout and GitHub publication are not included.

## Contract

Reduce inference, human attention, and elapsed time from approved intent to verified delivery. Preserve independent review, exact-candidate evidence, authority, and recovery. No automated product publication, new providers, Projects/Sessions redesign, or Creator installation changes are included. The build Manager remains responsible for efficiency until the GM passes operational acceptance.

## Sequential checklist

| Ticket | Outcome | Acceptance |
| --- | --- | --- |
| LEAN-01 | Preserve stage usage, failed attempts, explicit external exports, and optional work/outcome references using shared normalization | Cumulative/resumed/duplicate/parent-inclusive records reconcile; unknown and shared overhead stay visible; PR and feature views never sum overlapping work |
| LEAN-02 | Authenticated, persisted, allowlisted hot loop registration and one deterministic observer per source | Running Console discovers a real new loop without restart or agent polling; restart duplicates nothing; recorded state is distinct from worker liveness |
| LEAN-03 | Opt-in implement/verify/review/deterministic-accept and validation-only profiles | Existing candidate launches no implementer; approved brief skips AI briefing/acceptance; changed evidence invalidates acceptance; failed review returns to implementation owner |
| LEAN-04 | Per-role routing, compact packets, deterministic preflight | Configured routes and escalation reasons are recorded; denied authority stays denied; known prerequisites block launch; second identical failure blocks until cause changes |
| LEAN-05 | Deterministic findings and one consolidated nightly GM review | Single-owner daily invocation; unchanged inputs skip inference; failed review stays visible; timezone-aware local scheduler configuration; no automatic paid route or repeated diagnosis |
| LEAN-06 | Focused Overview/Factory efficiency and decision surfaces | Disabled/degraded supervision is explicit; findings name problem, owner and next action; delivery and infrastructure are separate; expanded activity lives on Work |

Phase 1 comprises LEAN-01/02; Phase 2 comprises LEAN-03/04; Phase 3 comprises LEAN-05/06. Later phases start after independent acceptance of the preceding phase.

## Evidence and cost accounting

Usage identity includes provider, session/run, response identity, and measurement source. Cached input and uncached input partition input; reasoning is an output subset. Missing telemetry is unknown, never inferred from account percentages. Registered external exports are permitted; scanning unrelated sessions is not. Preserve failed attempts, unfinished/abandoned expenditure, and shared/unattributed overhead.

* Tokens per merged PR: attributed tokens across the merged cohort, including retries/reviews, divided by distinct merged PRs.
* Tokens per shipped feature: attributed work tokens divided by features with deployment-bound product acceptance.
* Delivery lead time: claim to verified staging/product acceptance; report median, cohort and sample size.
* Accepted-work wait: local acceptance to verified deployment, including still-waiting work separately.
* Rework share: measured repairs and invalidated/repeated work divided by measured attributed tokens.
* Coordination share: measured orchestration/observation divided by measured attributed tokens.
* Coverage: registered participating sessions with usable usage divided by registered participating sessions.

PR and feature metrics are alternative overlapping views, not additive. Report regression/reopen counts and human intervention alongside efficiency. Dollar figures require a recorded pricing basis; subscription consumption is not an API invoice.

## Execution rules

Existing configurations retain behavior. Lean execution needs approved scope, adequate criteria, declared verifiers and authority. Validation-only uses an existing candidate; it cannot manufacture an implementation stage. Deterministic acceptance validates evidence, not subjective product quality. Evidence reuse requires candidate content, base/dependency revisions, requirements, verifier commands and environment inputs to match; unknown dependencies require revalidation. Sensitive changes retain stricter review. Completed and active runs are immutable.

Route every role to the least-expensive capable owner-configured model. Routine non-code defaults to Luna/medium when available; Terra handles harder bounded judgment; Sol needs complexity, risk or observed-failure justification. Provider configuration remains the compatibility fallback. No billing-route switches. Agent packets carry objective, constraints, changed facts, evidence references and next action, not histories. Human summaries explain outcomes and decisions.

## GM and rollout

Deterministic observers assemble changed findings and metrics. GM input contains changes since the last successful review, prior recommendations and owner decisions—not raw journals. Local scheduler defaults to 02:00 in the configured factory timezone (launchd/systemd). At most one consolidated invocation per scheduled day; no material change means no invocation. Failure is recorded and notified once, with retry next scheduled day or explicit owner request. Urgent containment uses preapproved deterministic actions. Spending, architecture, authority and product changes remain proposals.

Prove one existing candidate and one small implementation in isolated Faktori resources, recording invocations, available usage, wall time, intervention, rework and acceptance. Compare only equivalent cases; otherwise establish a baseline without claimed savings. No Creator changes or worker restarts before explicit rollout authority.

## Construction efficiency

Advisory initial estimates: Phase 1 180,000 tokens, Phase 2 220,000, Phase 3 180,000; low confidence until comparable accepted work supplies measurements. Each reserves approximately 15% management, 50% implementation, 25% verification/rework and 10% contingency. These are not native goal caps or completion criteria. Phase orchestrators start at Terra/high; independent consequential review may use Sol, mechanical tasks Luna/medium. Prefer one bounded implementer over gratuitous fan-out. Record measurement gaps rather than fabricate aggregate usage. Update the lean construction checklist with acceptance evidence and subsequent routing/estimate adjustments.
