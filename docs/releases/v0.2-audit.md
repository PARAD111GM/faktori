# v0.2 release audit

## Scope and observed results

The audit covers the assembled Faktori kit and the isolated local Console. It
does not activate, repair, restart, or upgrade another product installation.

- Browser journeys passed at 1280, 768, and 390 pixel widths across Overview,
  Projects, Decisions, Work, Sessions, Factory, and Settings: no page errors or
  document-wide horizontal overflow.
- One Work Kanban, ticket search, matched input/select height, bounded internal
  card scrolling, and project list/detail/reload/back navigation passed.
- Settings edit/review/save/persistence was previously exercised on this isolated
  Console; this pass retained those boundaries and the missing-catalog recovery.
- The initial full suite found one outdated assertion for the removed duplicate
  Sessions header. The assertion now checks recorded contact and absence of the
  redundant heading while preserving unknown-liveness assertions.
- Final deterministic test run: 525 tests across 70 files passed, plus strict
  TypeScript and production build. Skill verification passed for all 16 skills
  and the three provider entry maps.
- Clean installed-package verification passed for `faktori-0.2.0.tgz` on Node
  24.20.0, completing `npm run check`.

## Setup omission reproduced

A read-only report against an existing owner installation found a Codex catalog
entry but no runtime routes, no Jira sources, no GM runtime or nightly schedule,
and Claude/Cursor unselected. The new readiness command returned five unavailable
checks, zero verified checks, and `complete: false`. No credentials were exposed
and no integration was invoked. This is configuration evidence, not a claim that
the external coding sessions themselves cannot run.

The fix is an offline inventory plus an explicit agent handoff requirement:
selected integrations need bounded observed evidence; wanted-but-unconfigured
integrations need a next action; omissions require an owner decision, never an
implicit successful setup. See [the update guide](../agent-update-guide.md).

Live Jira access, newly authenticated Claude execution, and installation of the
GM scheduler remain separate owner-approved tasks. Package installation, a
visible Console, and configuration declarations do not establish these outcomes.
