# v0.2.10 — native full requirements-definition proposals

`faktori discovery draft <operator-config.json>` connects the immutable
requirements interview to native frontier-model generation of a full product
definition. The exact approved route, private raw/normalized evidence and
response-byte provenance travel with the proposed definition. Web/native target
requirements and live-product context remain bound to the owner's interview.

The proposal journal supports exact replay without another model launch and
rejects conflicting configuration, changed history, incomplete records and
altered artifacts. Provider failure or rejected output cannot create an accepted
definition, edit interview history or grant execution or release authority.
Native credentials remain in the vendor CLI; no billing fallback is introduced.

Operator-bounded retries can correct completed but invalid model definitions,
including inconsistent journey/requirement maps. Every original response and
corrective context stays retained. Auth/quota, uncertain execution, stale history
and capture/persistence failures cannot trigger that repair path.

Update the installed package and use the same explicitly approved native route
configuration as `discovery propose`, with a fresh proposal ID for this definition.
Keep histories/artifacts private and review the proposed definition separately.
See [definition drafting](../production/definition-draft.md) and
[observed execution status](../production/execution-status.md). Runtime/output
bounds do not establish financial/token caps or OS filesystem isolation.
