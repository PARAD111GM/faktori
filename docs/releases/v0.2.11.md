# v0.2.11 — requirements, design and delivery handoff

Accepted requirements now connect to a separately accepted product experience
and architecture design, then feed the existing delivery loop. The bridge binds
definition/design digests, complete interactions and accessibility states,
shared APIs/domain/data and target UI/native/runtime decisions. Live increments
retain client, contract, schema, migration and concurrent-work constraints.

Coherent slices and narrow dependency contracts inform context and ownership.
The existing accepted execution scope and inherited constraints remain intact.
Design changes invalidate affected consumers and downstream work; changed
artifacts require reacceptance. Missing approvals/bindings suppress execution.

The design file is pinned by canonical bytes and checked by existing preflight,
including realpath containment against parent-directory symlink escapes. Owner
declarations do not authenticate identity or prove visual/runtime acceptance.
This increment creates no provider, device, deployment or release observation.
Source typechecking/build and the complete source and clean installed-package
feature journeys passed, including design tampering and symlink containment.

Update the installed kit, then use `product design-inspect`, `design-canonical`,
`design-change`, `design-compile` and `design-loop-config`. Follow
[product design](../production/product-design.md) and
[execution status](../production/execution-status.md) for the observed gates.
