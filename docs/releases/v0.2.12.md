# v0.2.12 — observed baseline to next-feature discovery

This candidate adds a bounded bridge from product runtime observations to a
durable adopted baseline and the next owner-requested feature discovery session.
Local qualification and public production environments remain distinct. Public
adoption requires the existing exact release evidence; local observations cannot
supply publication, merge or deployment authority.

The next session retains the adopted source/artifact and compatibility context.
The owner supplies the new feature intent. Observation or adoption does not
authorize implementation, spending, publication or release.

Source typechecking/build and the complete source and clean installed-package
cycle passed. A real local authenticated persistent application received an
additive feature while preserving its old API/data, restart and restore paths.
Receipt drift, stale runtime, full capacity, interrupted persistence and exact
replay controls were exercised. Independent review findings were repaired and
source re-review found no residual high-confidence blocker.

The public route currently supports the existing Lean/GitHub release profile;
it has no observed valid public release-chain qualification. General unmanaged
product adoption and human evaluator calibration remain open. No production
adoption or public feature release has been observed.

Update the installed kit and follow [live product continuity](../production/live-product.md)
for `product observation-scope`, `observe`, `adopt`, `next-discovery` and
`live-journal`. Adoption does not widen the next feature's execution authority.
