# v0.2.13 — design drafting and existing-product adoption

Accepted requirements can now feed an attended native model design proposal,
with exact response provenance, bounded semantic repair and replay. The proposal
includes experiences, architecture and complete delivery slices; it grants no
owner approval. Existing design approval and delivery compilation remain the
only route to implementation. Strict wire schemas and reference validation
prevent optional-contract transport failures and spoofed question-gap bypasses.

Existing externally hosted products can use the explicit `external_hosted`
baseline profile. It binds source, OCI image configuration/manifest, protected
native verification and observed target/resource identities. It preserves
managed Lean/GitHub admission requirements and does not invent factory merge or
publication receipts. Adoption then feeds explicitly requested next-feature
discovery with the preserved client, contract and schema baseline.

Use [design drafting](../production/design-draft.md) and
[existing-product adoption](../production/existing-product-adoption.md) for the
new configuration and commands. Update the installed package before invoking
them; existing configurations continue to use their existing profiles.
