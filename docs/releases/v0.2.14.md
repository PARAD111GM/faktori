# v0.2.14 — bounded native supervision

An opt-in Console runtime profile connects the existing coordinator to one owned
Codex app-server thread. Preparation retains a paused goal before any turn;
execution requires separate bounded-turn permission, exact identity/context,
one explicit turn and terminal/paused-goal/process-exit evidence. Durable
inspection, cancellation and uncertain outcomes retain existing capacity and
recovery authority. Control records remain outside the model writable workspace.

Console startup injects trusted readiness through the existing queue bridge.
Automatic operation still requires fresh independent runtime evidence and an
operator attestation; schema availability and local protocol fixtures cannot
enable it. Default bounded exec delivery remains available. See
[Native supervision](../production/native-supervision.md).

The consolidated check now runs complete feature slices rather than a micro-unit
test loop, followed by installed-package verification. Historical unit tests
remain available separately. The native protocol journey covers preparation,
bounded execution, exact resume/replay, readiness expiry and fail-closed
recovery/cancellation using an explicitly local fixture.

The attended public qualification record now includes schema-2 adoption,
independent local backup restore and final iOS simulator/Android emulator
shared-backend journeys. Physical devices, production signing, store delivery,
real-owner discovery-to-generated-delivery, evaluator calibration and sustained
automatic operation remain separate release gates. This patch does not declare
FAKTORI fully production ready.

Actual native qualification found that activating a goal starts an unsolicited
turn before the explicit request on the installed runtime. The supervisor
retained uncertainty and stopped the attempt; no automatic witness or product
acceptance was issued. Native-goal automation remains unqualified. Source and
installed protocol fixture checks passed, while attended bounded execution
remains the delivery route. Updating requires the normal owner-controlled
package update and restart; installation alone does not activate this opt-in
profile or enable automatic dispatch.
