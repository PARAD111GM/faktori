# v0.2.18 — responsive Console and final qualification plan

The Console keeps FAKTORI's existing charcoal, paper and orange identity while
improving navigation, panel hierarchy, form readability and responsive layouts.
Phones use a consistent four-by-two navigation grid, readable form text and
larger primary touch targets. Tablet layouts collapse dense work areas before
they become cramped. Long artifact previews scroll within their own containers.

Keyboard navigation now moves focus to the selected view. Skip to content keeps
the current page, missing command tokens produce actionable inline feedback,
and initial loading and failed connection states are distinct. Live update
connections close on teardown. Reduced-motion preferences remain respected.
Command authorization, durable retry identities and provider authority retain
their existing contracts.

The [final qualification plan](../production/final-qualification-plan.md) sequences
the remaining prospective requirements-discovery-to-adoption journey, ongoing
live-product development, independent human calibration, physical native
distribution, safe automation and sustained outcomes. Each complete slice has
prerequisites, acceptance evidence, failure/recovery rules and an accountable
role. Pending human decisions and account/device resources remain explicit.

The complete local Chromium journey passed 23 checks across all eight views at
320, 390, 768, 1024 and 1440 CSS pixels, with populated details, short landscape,
keyboard/dialog behavior, loading/disconnection recovery, token refusal and
same-identity command replay. Sixty-two screenshots and an asset-bound report
were retained. Run-link text measured 8.99:1 contrast at rest and 7.92:1 on hover;
phone primary targets measured at least 44px. Independent static review found
no remaining blocking issue. CI now runs the same whole journey and retains its
synthetic evidence. Actual Safari, physical-device, on-screen keyboard and true
browser-zoom acceptance remain in the qualification plan.

Source and clean installed qualification must also pass on this candidate.
Previous version receipts do not transfer to changed bytes. These changes do
not merge the branch, publish a package, replace an active installation, deploy
a product or qualify store distribution or unattended generation.

Update through the normal owner-controlled installation path using the exact
reviewed package. Preserve configuration, credentials and private journals.
No state migration is required. Keep the existing attended delivery route until
the separate automation and production gates are accepted.
