# Faktori v0.2.2

Experimental patch release improving Console guidance, Kanban behavior, and role instructions.

## Changes

- Section info buttons open an accessible Operator's handbook with purpose, data source, and next action. Missing project-catalog messages explain recovery instead of exposing only an error code.
- Uses the supplied combined FAKTORI logo and repairs the empty Kanban surface.
- Kanban follows Jira board column order and status-ID grouping, retains empty configured columns, and scrolls horizontally without the fixed nine-column layout. Unmapped tickets stay visible separately.
- Jira sources accept optional `boardId`. Automatic discovery selects only an unambiguous board; configuration failures preserve tickets and explicitly label missing or stale column information. Existing server-side authentication is reused.
- Role assignments include an optional multiline Role Prompt, inherited by products and pods. Console-managed dispatches and explicit resume targets include it in the approved context; changed admitted context is rejected. Named GM roles can supply prompts; nightly GM retains its configured model/provider route.
- Existing standalone Manager/Lean CLI loops and Manager-connected external sessions do not automatically inherit Factory Role Prompts. Permissions and publication authority are unchanged.

## Updating

Use the [agent update guide](../agent-update-guide.md). Update the installed backend and Console assets together, then safely restart only the Console when its ownership/admission conditions permit. Browser refresh alone does not activate Jira column ingestion or Role Prompt persistence/dispatch. Do not interrupt product workers or alter their configurations implicitly.

Role Prompt changes use Settings → Review changes → Confirm & save and require a safe Console restart. Do not store credentials in prompts. If Jira has multiple matching boards, configure the intended source's `boardId` as a positive numeric string.

This release does not configure missing integrations, activate a GM installation, authenticate providers, or claim live Jira/product delivery verification. Source tests and package verification are distinct from upgrading an owner's running installation.
