# v0.2.4 — Subscription-efficient delivery controls

## Source changes

- Added deterministic subscription routing with configured route preference,
  shared account-pool reservations, completion headroom, freshness and external
  pressure. Advisory estimates remain separate from provider-native capacity;
  paid fallback remains off without explicit authority.
- Added graph-backed role-queue projection and Console workflow facade. Queue
  activity is independent from tracker status, claims/launch intent/receipts are
  replayed from the existing coordinator journal, stale callbacks are ignored,
  and uncertain restart state is inspected rather than relaunched.
- Added an owner-private queue source with preconfigured runtime-work binding,
  optional live tracker/graph authority overlay and legacy-scope exclusion.
  Automatic queue admission requires current trusted transport, native-goal,
  supervision and witnessed-delivery evidence. Release never merges a PR.
- Added persistent local preview registration, process identity observation,
  separate agent/human browser contexts, revision invalidation and feedback
  batch records. Process controls select server-configured operation IDs;
  authenticated feedback is bounded and revision-bound.
- Added narrow read-only senior consultations with original-builder resumption,
  immutable feature-scope attribution and provider/model usage breakdowns.
- Packaged the concise-ticket, feature-sized-PR guidance in `AGENTS.md`,
  `CLAUDE.md`, generated provider entry maps and kit updates.
- Added Console type checking to the release check and a shutdown barrier so
  accepted but unstarted commands cannot launch after the runtime closes.
- Kept an unverified preview launch in durable uncertainty instead of allowing
  duplicate starts; cleanup never signals an unverified process. Candidate
  identity probes now honor the configured bounded deadline rather than an
  unrelated one-second subprocess cap.
- Bound preview shutdown to a stable process identity and require whole-group
  absence before clearing it, including exit-callback races on Linux.
- Serialized native-estimate admissions behind untranslatable active holds,
  recorded terminal reservation states on provider setup failures, and expired
  automatic-readiness attestations after two minutes (future dates fail closed).

## Updating

Read [subscription-efficient delivery](../subscription-efficient-delivery.md).
Update the package and Console assets together, preserve the existing journal
and active workers, then start with shadow and one attended Faktori-only item.
Configure only existing capabilities: one provider and local/GitHub is enough;
Jira, Slack and n8n are optional.

Do not enable automatic queue admission until the configured controller has
observed its current transport, native goals, wake-up/supervision and witnessed
delivery bindings. A `/goal` prompt, stale readiness file or timer expiry is not
evidence. Do not change credentials, purchase inference, merge, deploy, restart
unknown workers or touch live Twinzy as part of this update.

The Console distinguishes `shadow`, `attended`, and `automatic` evaluation;
inspect `automaticReady` and `capabilityBlockers` before treating a queue as
eligible for wake-up.
