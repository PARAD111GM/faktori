# v0.2.5 — Attended discovery spike preparation

Source candidate: inventory all 16 shipped skills against product discovery and
delivery outputs; expose a pure `faktori spike prepare <request.json>` command
and `faktori/production` export; ship a deliberately incomplete example, stage
handoffs, intervention template and attended web runbook.

Preparation validates a bounded request and produces a deterministic
request-digest-bound packet. It preserves raw intent and missing decisions; it
does not discover requirements, inspect declared resources, execute commands,
call providers, create authority, publish or deploy. Resource declarations remain
unobserved, all stages start not_started, and executionReady/productionReady stay
false even with owner-selected resources. No new automatic dispatcher is added.

The package and lockfile versions advance together. Existing installations,
workers, journals and credentials are unchanged. Use matching kit/Console assets
through the existing approved update path if installing this candidate later;
the command itself needs no migration, credential or integration setup.

Verification and limitations belong in
[the preparation report](../production/preparation-report.md). Source/package
checks do not establish an attended provider journey, a deployed product, live
acceptance or efficiency savings. The next product gate is the selected owner's
raw idea, followed by approved disposable execution/deployment resources and
real requirements discovery. This is not the v0.3 attended-production tier.
