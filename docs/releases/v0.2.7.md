# v0.2.7 — native executable binding and discovery model handoff

An attended qualification exposed that Lean preflight checked the configured
CLI executable while native launch invoked another `codex` from PATH. Native
launch now honors the exact configured executable. Existing direct callers
retain `codex` as their default. Process identity, lifecycle and cancellation
remain on the existing execution boundary. A path and availability check do not
establish vendor integrity, authentication, model access or sandbox qualification.

The loop retains private raw capture and complete normalized provider artifacts
before response validation. Artifacts use exclusive private files and durable
writes; capture bounds and overflow flags remain explicit. Compact receipts no
longer discard the evidence needed to inspect failures and repair/review turns.

Lean workers hand verification to the controller rather than repeat protected
browser journeys inside a sandbox that may deny localhost binding. Independent
review stages use fresh provider attempts; review ordinals no longer consume the
repair retry allowance. Repair ceilings and required sensitive review passes are
unchanged.

Review prompts explicitly specify string findings, including a repair-response
example. Invalid structured responses still fail closed; an actionable review
does not become an accepted receipt merely because its prose is plausible.

Codex reconnect-progress notices for recognized transient server errors can
recover only after a clean native completion and exit zero. The model response
remains the final summary; reconnect diagnostics and complete events remain
retained. Fatal, authentication, quota, authority, cancellation, malformed,
nonzero-exit and unresolved errors still block success, including contradictory
error aliases on a completion event.

`faktori discovery import-proposal <history> <response.json> <id>` imports a
structured model response without manual provenance editing. It reads the
bounded, canonical, unaliased response file, binds its exact file-byte digest,
and appends a model proposal to the interview history. Exact retries are
idempotent; conflicting IDs and model-supplied operator/authority fields fail.

Model names available inside an app do not establish compatibility with a
separately installed CLI. The attended operator must observe the selected
executable/version, its native catalog and an actual representative request.
Do not replace a rejected subscription route with separately billed inference.

## Update and qualification

Rebuild/reinstall the kit and explicitly configure the intended native CLI path.
No existing factory state migration or credential change is required. On the
pinned toolchain, run the consolidated production feature acceptance, typecheck,
build and packed CLI acceptance. The implementation status distinguishes source
and installed checks from actual provider/product and production release evidence.
