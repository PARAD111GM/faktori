# v0.2.8 — attended native requirements discovery

`faktori discovery propose <operator-config.json>` connects the saved raw-idea
interview to the operator's existing native Codex route. It renders the adaptive
prompt/schema, retains bounded raw and complete normalized provider artifacts,
validates the exact output and appends only a sourced model proposal.

Explicit native approval, canonical workspace/history/artifact paths, a selected
executable/model and bounded runtime/retries are required. The native vendor's
credentials remain untouched. No provider fallback, owner answer, accepted
definition, application execution or release authority is inferred.

Exact retry checks the recorded configuration and response-byte digest without
launching another provider. Conflicting IDs, malformed/forged responses, failed
native turns, overflow and stale history cannot append. Failures retain private
evidence. Runtime/output limits do not imply token or financial caps; bounded
context does not establish OS filesystem isolation.

Update the installed kit, prepare a private artifact directory, and follow
[the discovery handoff](../production/discovery-model-handoff.md). Existing
interview histories and the explicit manual import path remain compatible.
Source/fixture and installed native qualification are reported separately in
[execution status](../production/execution-status.md); this increment does not
close hosted web, Android, live-product or automatic-operation gates.
